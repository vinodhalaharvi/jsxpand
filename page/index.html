JSX from abbreviations

Type a few letters; get components the way this codebase writes them. Every reading is scored by what the code below does, and the best three are shown.

Letters run together are split for you. Optional: > child, + sibling, .value a prop value (btn.out → variant="outline"), *3 repeat.

Behind the scenes

Reading the input left to right is a grammar with one rule, Read ::= ε | Piece Read: the same shape as tiling a strip with tiles of different lengths, whose generating function is a fraction like the Fibonacci one.

Each piece is scored by three learned numbers multiplied together:

FactorWhat it isExample
AbbreviationHow likely a typist writes these letters for that name: the first letter kept, others kept or dropped, the end of a word cheap to leave off.hdr from Header
PlacementHow often that component sits inside the open parent in this code: the learned transition.CardHeader in Card: 11 of 29
WrapperWhen the component never sits there directly, the usual in-between component, at a cost.Button in Card → via CardFooter

The search is the dyna package: one coalgebra (every way to read the next piece) folded with three semirings at once.

SemiringGives
(max, +) on log-probabilities, kept best threeThe ranked expansions: Viterbi
(+, ×) on countsHow many readings there are
(+, ×) on probabilitiesTheir total, so each result shows its share

A subproblem is "this much text read, these components still open", so a reading that reaches the same point the same way is solved once, not again for every way of getting there.
